# 世界模型设计文档

## 1. 定位与边界

### 1.1 定位

世界模型是一个**持续运行的状态服务**，贯穿整个任务执行生命周期。它不是流水线上跑一次就结束的阶段，而是被感知前端持续更新、被 grounding / planner / control 持续查询和回写的中心状态层。

### 1.2 职责

- 存储场景中所有实体的类别、位姿、几何信息与空间关系
- 存储机器人自身状态（关节角、末端位姿、夹爪状态等）
- 维护状态的时间戳、置信度与来源信息
- 提供面向不同消费者的查询接口
- 管理状态快照，支持 diff 与回溯

### 1.3 不负责

- 可达性判断、力约束评估（属于 planner / control）
- 任务分解与步骤排序（属于 planner）
- 语义绑定（属于 grounding）
- 感知数据采集与特征提取（属于感知前端）

世界模型**提供数据**给下游模块查询，不替下游做决策。

## 2. 表示结构

### 2.1 环境侧：3D 场景图

环境状态以场景图（Scene Graph）为核心表示，由节点（SceneNode）和边（SceneEdge）构成。

现有基础：`interfaces/scene_graph.py` 中已定义 `SceneGraph`、`SceneNode`、`SceneEdge`。

- **SceneNode**：每个实体一个节点，包含 `node_id`、`label`、`node_type`、`center_pose`（Pose7D）、`bbox_extent_m`、语义标签、状态标签、来源归因（`SourceAttribution`）
- **SceneEdge**：节点间的关系，包含 `relation_type`、`relation_family`、方向性、数值属性与来源归因

所有实体（物体、人、容器、家具）统一建模为 SceneNode。人作为多关键点实体，通过 `node_type` 区分，关键点信息存储在 `properties` 字段中。不需要为人单独建立一套表示体系。

### 2.2 机器人侧：本体状态

机器人自身状态不属于场景图，而是世界模型中独立维护的部分，包括：

- 关节角度向量
- 末端执行器位姿（Pose7D）
- 夹爪状态（开合度、是否持有物体）
- 运动模式（idle / executing / error）

本体状态的更新来源是编码器、力觉传感器等本体感知通路，更新频率与控制频率一致（数百 Hz），独立于视觉感知通路。

### 2.3 空间关系的职责划分

世界模型负责维护**几何可直接推算的空间关系**：

| 关系类型 | 推算依据 | 示例 |
| --- | --- | --- |
| `supports` / `supported_by` | 垂直间距 + XY 重叠 | 杯子在桌子上 |
| `contacts` | 包围盒距离 | 两个物体相邻 |
| `near` | 欧氏距离阈值 | 瓶子在杯子附近 |
| `inside` | 包围盒包含关系 | 物体在容器内 |

**功能性关系**（`graspable`、`obstructed_by`、`reachable`）需要结合机器人构型、夹爪约束等信息，由 planner 层判断，不在世界模型中预算。

现有基础：`modules/world_model/scene_graph_builder.py` 中的 `SceneGraphBuilder` 已实现 `supports`、`contacts`、`can_reach` 的几何推算。

## 3. 感知前端与世界模型的接口

### 3.1 感知前端的产出

感知前端负责从传感器数据中提取结构化观测，预期流程为：

```
RGB-D / LiDAR → 点云重建 → 等变网络 / SE(3) Transformer（位姿估计）→ 场景图构建
```

感知前端的输出是一组 `SceneObjectObservation`（已定义于 `scene_graph_builder.py`），每个观测包含物体 ID、类别、位置、包围盒、属性与来源归因。

### 3.2 世界模型的接收与处理

世界模型接收感知前端的观测后：

1. 与已有实体做实例关联（同一个杯子在不同帧中应关联为同一节点）
2. 更新匹配实体的位姿、置信度与时间戳
3. 注册新发现的实体
4. 标记丢失的实体（降低置信度，而非立即删除）
5. 重新计算受影响的空间关系

## 4. 时序管理策略

### 4.1 核心路线：预测为主，感知校验

世界模型同时维护两种状态来源：

- **预测态**：动作执行后，根据动作语义推算的预期状态变化（如执行 `pick(cup)` 后，cup 从 table 转移到 gripper）
- **观测态**：感知前端推送的实际观测结果

预测态用于快速推进（低延迟、无感知开销），观测态用于校验和修正。

### 4.2 置信度衰减

每个状态条目携带时间戳和置信度。置信度随时间自动衰减，衰减速率按实体类型区分：

- 固定家具：衰减慢（位置几乎不变）
- 可操作物体：衰减中等
- 人 / 动态实体：衰减快（运动状态变化频繁）

当置信度低于阈值时，世界模型主动向感知前端发起观测请求。

### 4.3 事件触发的感知请求

除了置信度衰减触发外，以下事件也会触发定向感知请求：

- 动作执行前：对目标对象进行一次确认观测
- 动作执行后：对受影响区域进行一次验证观测
- 预测态与观测态冲突时：对冲突实体进行高置信度重观测

### 4.4 分层更新频率

不同类型的状态使用不同的更新频率：

| 状态类型 | 更新频率 | 数据来源 |
| --- | --- | --- |
| 机器人本体状态 | 控制频率（数百 Hz） | 编码器、力觉传感器 |
| 当前操作目标物体 | 动作相关时高频，空闲时低频 | 视觉感知 |
| 背景环境 | 低频扫描 | 视觉感知 |
| 人 / 动态实体 | 始终高频 | 视觉感知 |

### 4.5 快照粒度

采用事件驱动的快照策略：

- 动作开始前：存一次快照
- 动作结束后：存一次快照
- 感知检测到显著变化时：存一次快照

快照支持 diff 对比和回溯，用于重规划和执行 trace 审计。

## 5. 与相邻模块的关系

```
感知前端 ──观测推送──→ 世界模型 ←──状态回写── control
                          │
              ┌───────────┼───────────┐
              ↓           ↓           ↓
          grounding    planner     control
         (语义查询)   (关系查询)  (位姿查询)
```

### 5.1 grounding → 世界模型

grounding 层将自然语言中的对象引用绑定到场景中的具体实例。它需要按语义属性查询世界模型，例如"红色的杯子"、"桌子上的瓶子"。

查询维度：标签、语义标签、空间关系、属性。

### 5.2 planner → 世界模型

planner 消费 `WorldState` 和 `SceneGraph`，用于判断前置条件是否满足、构建动作序列。它按关系查询，例如"哪些物体在桌子上"、"cup 当前被什么支撑"。

现有基础：`modules/planner/planner.py` 中 `TaskPlanner.build_plan()` 已接收 `WorldState` 参数。

### 5.3 control → 世界模型

control 层在执行动作后，将观测到的状态变化回写到世界模型。它按位姿查询目标物体的当前几何信息。

现有基础：`modules/control/executor.py` 中 `PlanExecutor.execute()` 已通过 `world_model.update()` 回写状态。

### 5.4 感知前端 → 世界模型

感知前端以 `SceneObjectObservation` 列表的形式推送观测数据。世界模型负责实例关联、状态融合和关系更新。

## 6. 现有代码基础与扩展方向

### 6.1 可直接复用

| 组件 | 路径 | 说明 |
| --- | --- | --- |
| `SceneGraph` / `SceneNode` / `SceneEdge` | `interfaces/scene_graph.py` | 场景图核心表示 |
| `WorldState` / `ObjectState` | `interfaces/world_state.py` | 世界状态顶层结构 |
| `SourceAttribution` / `Pose7D` | `interfaces/common.py` | 来源归因与位姿类型 |
| `SceneGraphBuilder` | `modules/world_model/scene_graph_builder.py` | 几何关系推算 |
| `WorldModelStore` | `modules/world_model/state_store.py` | 状态存储基础框架 |

### 6.2 需要扩展

- **WorldModelStore**：当前只持有单一 `WorldState`，需要扩展为支持快照历史、置信度衰减、事件触发机制
- **ObjectState**：需要增加时间戳、置信度字段
- **SceneNode**：需要支持多关键点实体（人体骨骼等），可通过 `properties` 字段承载
- **查询接口**：需要为 grounding / planner / control 提供不同维度的查询方法
- **实例关联**：需要在世界模型层实现跨帧的实体匹配逻辑

## 7. 开放问题

以下问题在当前阶段不阻塞设计，可在实现过程中逐步明确：

- **冲突解决策略**：预测态与观测态不一致时的具体裁决规则（以观测为准？置信度对比？）
- **冷启动流程**：机器人进入全新环境时，世界模型如何初始化（全量扫描 vs 渐进发现）
- **存储机制**：快照存内存环形缓冲还是持久化归档，保留策略如何定
- **置信度衰减函数**：具体的衰减曲线和阈值参数，需要通过实验标定
